# LIMYZINOV SHOP

Telegram-магазин, админ-панель, поддержка и обработчики оплат в одном Python-процессе. Публичного сайта нет. Отдельный сервер базы данных не нужен: SQLite создаётся в `data/shop.db` рядом с приложением.

Интерфейс работает как один аккуратный экран: перед показом нового сообщения бот удаляет свой предыдущий экран, а после обработки убирает из чата пользовательские команды и введённые данные. Во вложенных разделах есть контекстная кнопка «Назад», а главное меню всегда доступно отдельной кнопкой. Заголовки поддерживают Telegram Premium emoji и автоматически переходят на обычные emoji, если аккаунту владельца они недоступны.

## Быстрый запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -m app.main
```

Для Windows активация окружения: `.venv\Scripts\activate`. Минимально в `.env` нужен только `BOT_TOKEN`. Способ оплаты появляется в боте лишь тогда, когда для него заполнены ключи.

## RollyPay

Заполните `ROLLYPAY_TERMINAL_ID`, `ROLLYPAY_API_KEY` и `ROLLYPAY_SIGNING_SECRET`. В настройках кассы укажите Callback URL:

```text
https://ваш-домен.ru/rollypay/callback
```

Сначала проверьте полный цикл с `ROLLYPAY_TEST_MODE=true`, затем включайте боевой режим. Callback проверяет HMAC-подпись, ID заказа, ID платежа, валюту и сумму. Каждый заказ имеет UUID, повторная доставка callback не засчитывает покупку второй раз, а безопасный журнал сохраняет результат события и число его доставок.

## Админ-панель и каталог

Владелец с Telegram ID `8464597898` уже указан в коде — добавлять его в `.env` не нужно. После запуска отправьте боту `/admin`. Переменная `ADMIN_IDS` остаётся необязательной и нужна только для добавления других администраторов через запятую.

Готовых товаров в каталоге нет. В админ-панели можно создавать свои товары, менять цену СБП и цену в Stars, редактировать название/описание и скрывать позицию. Для каждого товара обязательны обе цены; покупатель выбирает СБП, Telegram Stars или наличные при получении. Каталог хранится в `data/shop.db`, редактировать Python-файлы не нужно.

Для физического товара бот до оплаты спрашивает способ получения. Доставка требует полный адрес и добавляет `50 ₽` при оплате по СБП или наличными либо `25 ⭐` при оплате Stars. Самовывоз доступен без доплаты только из ТЦ «Гостиный Двор». Затем бот спрашивает дату получения (число месяца, заказы принимаются на 30 дней вперёд) и время в окне `10:00–23:00` с шагом в полчаса. Дата и время сохраняются вместе с заказом.

Третий способ оплаты — **«Наличными при получении»**. Заказ создаётся сразу без платёжного шлюза и мгновенно приходит всем администраторам с суммой, адресом и графиком получения. Кнопка доступна, только если у товара задана цена в рублях; цифровые товары оплачиваются онлайн.

## Выдача заказов и отзывы

В админ-панели есть раздел «Заказы»: оплаченные заказы с ником покупателя, суммой и способом оплаты, переключатель «ждут выдачи» / «все оплаченные» и счётчик ожидающих на главном экране панели. В карточке заказа — товар, цена, статус, покупатель (`@username`, имя и числовой ID), номер заказа, время создания/оплаты/выдачи, адрес, дата и время получения.

Кнопка **«Подтвердить выдачу»** помечает заказ выполненным и отправляет покупателю сообщение «Спасибо за заказ» с кнопкой **«Оставить отзыв»**. Статус при этом остаётся «Оплачен» — выдача хранится в отдельном поле `issued_at`, чтобы не ломать подсчёт продаж в аналитике. **«Вернуть в „ждёт выдачи“»** отменяет подтверждение, **«Заказ не выполнен»** после переспрашивания переводит заказ в «Отменён» и уведомляет покупателя.

Отзыв — от 1 до 5 звёзд (кнопкой или числом в чате) плюс необязательный комментарий: бот спрашивает текст, кнопка «Пропустить комментарий» завершает без него. Отзыв приходит всем администраторам со звёздами, ником покупателя и ссылкой на заказ. Повторная оценка того же заказа не принимается, а в «Моих заказах» у покупателя появляется кнопка «Оставить отзыв» для выданных заказов без оценки; напомнить о ней можно кнопкой в карточке заказа.

Таблица `reviews` и колонка `issued_at` создаются автоматически при запуске — старые базы не пересоздаются.

Там же доступны промокоды, аналитика и журнал оплат. Аналитика показывает число пользователей, продажи за 24 часа/7 дней/30 дней, конверсию пользователей в покупателей и популярные товары. Рубли и Stars считаются отдельно.

## Бонусы и реферальная программа

В разделе «Бонусы» пользователь видит баланс, вводит промокоды, историю начислений и персональную ссылку. За нового приглашённого пользователя начисляется 100 бонусов пригласившему и 50 бонусов приглашённому. Повторная регистрация, повторное использование промокода и самоприглашение не начисляют бонусы.

Ежедневная серия выдаёт 10, 15, 20, 25, 30, 40 и 50 бонусов за семь последовательных дней, после чего начинается заново. Пропуск дня сбрасывает серию; повторно получить награду за тот же день нельзя. Новый день считается по часовому поясу Екатеринбурга.

Раз в неделю пользователь может открыть секретное персональное предложение со скидкой 10–20%. Оно действует ровно два часа с момента первого открытия и может быть использовано только один раз.

## Поддержка

Кнопка «💬 Поддержка» принимает текст, фото, видео, документы и голосовые сообщения. Обращение сохраняется в SQLite и отправляется владельцу `8464597898`. Владелец отвечает покупателю кнопкой «✉️ Ответить», может просматривать новые, все и закрытые обращения в `/admin`. Для сообщений действует защита от спама.

## Хостинг

Команда запуска: `python -m app.main`. Технический HTTP-сервис слушает `0.0.0.0:8080`. Доступны только `GET /health`, `POST /rollypay/callback` и `POST /webhooks/rollypay`; запрос к `/` возвращает 404. Можно использовать готовый `Dockerfile`.

Папка `data/` должна храниться на постоянном диске. Секреты задавайте через `.env` или панель переменных окружения хостинга; `.env` исключён из Git.
