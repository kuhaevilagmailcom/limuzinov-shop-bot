# Предложка с модерацией в группе

Telegram-бот на Python 3.11+ и aiogram 3. Пользователь отправляет сообщение боту в личку, а заявка появляется в группе модерации. Для альбомов бот дополнительно создаёт карточку управления с кнопками, чтобы модерация оставалась доступной даже если Telegram не показывает клавиатуру на элементах альбома. Отдельные администраторы и их личные чаты не нужны: кнопками может пользоваться любой участник группы.

## Возможности

- Поддерживаются текст, фото, видео, кружки, голосовые, GIF, стикеры, файлы и альбомы.
- Для одиночного текста или медиа кнопки находятся на исходном сообщении; после решения текст/подпись обновляется на месте.
- Если длинная подпись или текст не оставляют места для данных отправителя в лимите Telegram, бот сохраняет исходный контент и добавляет отдельную карточку с именем, @username и ID отправителя.
- Альбомы остаются альбомами. Бот пытается прикрепить кнопки к каждому элементу и всегда добавляет отдельную карточку управления с рабочими кнопками; успешно прикреплённые кнопки не удаляются.
- Пока решение не принято, в карточке не выводится строка «Статус: на проверке». После решения указывается итог и имя с Telegram ID модератора.
- В личном чате остаётся одна постоянная кнопка: **Узнать, кто выложил**. Пользователь нажимает её, отправляет ссылку на публикацию из настроенного канала (`https://t.me/c/1234567890/456` или `https://t.me/ChannelName/456`), оплачивает счёт RollyPay и получает карточку с именем, @username и Telegram ID автора. Начальная цена — 100 ₽; её меняет администратор командой `/setinfoprice СУММА`.
- Бот проверяет RollyPay самостоятельно каждые 12 секунд и после подтверждения отправляет результат в личный чат покупателя. Выбор ссылки хранится в SQLite 15 минут, в том числе после перезапуска; `/cancel` сбрасывает ожидание.
- «Жду посты» и «Подпишитесь на нас» под каждой заявкой и обработанной карточкой готовят два заранее заданных объявления в канале; публикация доступна только администраторам группы модерации и требует отдельного подтверждения. Это сообщения в канале для подписчиков, а не личные сообщения людям из /users.
- Отклонить — сообщает отправителю, что предложение не принято.
- Ответить — можно просто свайпнуть по заявке в группе модерации и ответить на неё, не нажимая кнопку. Работает и для отдельных элементов альбома, и после принятия/отклонения. Кнопка «Ответить» тоже остаётся доступна; ответ уходит пользователю в личку с цитатой его предложения.
- Заблокировать — блокирует пользователю отправку новых предложений. Блокировки сохраняются в SQLite. Участника группы модерации бот заблокировать не даст; если такой участник был заблокирован ранее, при следующем обращении бот снимет блокировку после подтверждения его членства.
- Команда /top показывает рейтинг модераторов и статистику опубликованных постов. /top и /users работают в группе модерации, а также в личных сообщениях бота для подтверждённых администраторов группы; при неверном ID группы бот объясняет, что нужно проверить MODERATION_CHAT_ID.
- /users показывает постраничный список известных боту пользователей с именем, @username и ID. /done ТЕКСТ доступна только администраторам группы модерации, запускает рассылку по сохранённым пользователям бота после подтверждения; /done ответом на сообщение пересылает это сообщение тем же способом.
- Команда /help показывает доступные команды.
- Команда /unblock USER_ID в группе модерации снимает блокировку.
- Команда /cleanbuttons, отправленная ответом на сообщение в группе модерации, убирает клавиатуру именно с этого сообщения. Команда /cleanbuttons POST_ID убирает клавиатуру у поста в канале публикации; POST_ID — число в конце ссылки.
- После решения кнопки принятия/отклонения заменяются статусом и возможностью ответить, повторно обработать заявку нельзя; на карточке указываются имя и Telegram ID модератора, который принял, отклонил или заблокировал пользователя. Если сообщение нельзя редактировать, информация о решении отправляется ответом на карточку. При запуске бот обновляет клавиатуры ожидающих заявок (заменяет старые кнопки на актуальные) и очищает клавиатуры обработанных карточек.
- Иконки интерфейса используют набор [TgAndroidIcons](https://t.me/addemoji/TgAndroidIcons): в сообщениях — custom emoji, на кнопках — встроенные иконки Telegram. При явном отказе API бот повторяет отправку с обычными emoji.

**Важно:** для отображения именно custom emoji у владельца бота должен быть Telegram Premium. Иконки в сообщениях доступны в личных чатах, группах и супергруппах; в канал копируется исходное содержимое пользователя, а в конце добавляется цитируемый дисклеймер.

## Настройка

1. Создай бота через @BotFather.
2. Установи зависимости: pip install -r requirements.txt.
3. Укажи BOT_TOKEN в переменных окружения хостинга или в локальном .env.
4. Укажи MODERATION_CHAT_ID — ID группы, куда приходят заявки и кнопки.
5. Укажи DESTINATION_CHAT_ID — ID отдельного канала, куда отправлять принятые предложения. Эти ID должны быть разными, если нужна публикация из группы в канал.
6. Добавь бота в группу модерации и укажи её ID в MODERATION_CHAT_ID. Чтобы проверка членства работала надёжно и бот мог защищать участников группы от блокировки, выдай боту права администратора в группе. Для канала добавь бота администратором с правом публикации и укажи ID именно канала.
7. На BotHost команда запуска — python main.py. После изменения кода или переменных окружения полностью перезапусти приложение, чтобы запустился новый процесс.

Пример переменных окружения:

- BOT_TOKEN — новый токен бота.
- MODERATION_CHAT_ID=-5106639548 — группа модерации (пример).
- DESTINATION_CHAT_ID=-1001234567890 — отдельный канал публикации (пример; используй свой реальный ID).
- DATA_DIR=/app/data — каталог постоянных данных BotHost. Если `DB_PATH` не задан, SQLite сохраняется в `/app/data/suggestions.sqlite3`, а прежняя база из каталога приложения переносится через SQLite backup при первом запуске, если она сохранилась.
- DB_PATH=/app/data/suggestions.sqlite3 — необязательный явный путь к базе SQLite. Не указывай каталог приложения `/app/suggestions.sqlite3`: он может очищаться при пересборке.
- ROLLYPAY_API_KEY и ROLLYPAY_TERMINAL_ID — ключ и касса RollyPay.
- ROLLYPAY_API_BASE=https://rollypay.io — официальный API endpoint.
- POST_AUTHOR_INFO_PRICE_RUB=100 — стартовая цена сведений об авторе; администратор меняет её командой `/setinfoprice 150`.
- PUBLIC_SITE_BASE_URL=https://mgnvpn.ru — сайт с callback и страницами результата оплаты.

Если используется существующая SQLite-база, старые заявки и блокировки сохраняются. Пользователи из старых заявок автоматически попадут в список /users; новые пользователи записываются при первом обращении в личный чат с ботом. Для заявок, опубликованных до установки этой версии, статистика периодов использует дату создания заявки как приблизительную замену времени публикации; новые публикации получают точную отметку времени. Явная переменная DESTINATION_CHAT_ID имеет приоритет над старым адресом, сохранённым в базе.

## Важно

- Просматривать /top и /users в группе модерации могут её участники; для вызова из лички пользователь должен быть администратором этой группы. Рассылку /done и публикацию объявлений через кнопки могут запускать только администраторы группы модерации. Telegram Bot API не выдаёт полный список подписчиков канала; объявление в канал видно его аудитории, а личная рассылка /done доступна только по пользователям, известным боту.
- Не добавляй токен в GitHub. Храни его только в защищённых переменных окружения хостинга.
- Не запускай два экземпляра polling-бота одновременно с одним токеном.
- Старая кнопка «Связаться с владельцем» была клавиатурой в личном чате пользователя, а не кнопкой под постом. При команде /start и при отправке уведомления бот снимает такую клавиатуру; если она осталась видна, нажми /start один раз. Убрать клавиатуру из чата, в который пользователь не отправляет сообщений, бот не может. После решения заявки кнопки принятия/отклонения заменяются статусом; ответ пользователю остаётся доступен. Исторические посты канала нельзя автоматически перебрать через Bot API, если их ID не сохранены; для них используй /cleanbuttons POST_ID. Новые публикации бот отправляет с текстовыми ссылками в содержимом поста (или отдельным сообщением для неподдерживаемого типа медиа). Кнопки модерации с объявлениями остаются в группе модерации, а не в канале. Бот не может автоматически перебрать старые посты канала, если ID не сохранены.
- Если /start не отвечает после деплоя, проверь логи запуска: в них должно быть Started as @... . Убедись, что хостинг запустил нужную ветку и что не работает второй экземпляр бота с тем же токеном.
- Если в логах написано, что группа модерации и канал публикации имеют одинаковый ID, бот не будет считать заявку опубликованной: укажи разные ID.
- Если текст нужно опубликовать вместе с фото или видео, отправляй текст именно в подписи к медиа. Telegram не позволяет превратить два отдельно отправленных сообщения в одно без изменения исходного содержимого.

## Проверки перед обновлением

- Сделай резервную копию текущего файла SQLite вместе с WAL/SHM (лучше штатным SQLite backup API) и проверь, что DB_PATH указывает на прежний постоянный каталог. Старые ссылки требуют сохранённой записи о публикации; если база безвозвратно потеряна, одной ссылки недостаточно, чтобы безопасно восстановить chat_id и message_id. Сама миграция не удаляет таблицы или пользователей.
- Запускай тесты: `python -m unittest discover -s tests -v`. Запуск бота после обновления должен быть в одном экземпляре.
- Проверь /top, /users в группе модерации и личке администратора, публикацию текстового/медиа-поста, ссылки, оба объявления с подтверждением. Чтобы бот мог писать в канал, нужны права администратора на публикацию.
