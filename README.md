# Предложка с модерацией в группе

Telegram-бот на Python 3.11+ и aiogram 3. Пользователь отправляет сообщение боту в личку, а само сообщение с кнопками появляется в группе модерации — отдельная карточка не создаётся. Отдельные администраторы и их личные чаты не нужны: кнопками может пользоваться любой участник группы.

## Возможности

- Поддерживаются текст, фото, видео, кружки, голосовые, GIF, стикеры, файлы и альбомы.
- Исходное сообщение (текст или медиа с подписью) становится карточкой модерации: отдельная карточка не создаётся.
- Кнопки и статус заявки находятся на исходном сообщении; после решения его текст/подпись обновляется на месте.
- Альбомы остаются альбомами; кнопки прикрепляются к первому элементу альбома, чтобы не разрывать группу.
- Принять — публикует только исходное предложение в целевом чате, без дополнительных сообщений и дисклеймеров.
- Отклонить — сообщает отправителю, что предложение не принято.
- Ответить — участник группы отвечает на сообщение-подсказку прямо в группе; ответ уходит пользователю в личку с цитатой его предложения.
- Заблокировать — блокирует пользователю отправку новых предложений. Блокировки сохраняются в SQLite.
- Команда /unblock USER_ID в группе модерации снимает блокировку. Любой участник этой группы может выполнить её.
- После решения кнопки убираются, повторно обработать заявку нельзя.
- Иконки интерфейса используют набор [TgAndroidIcons](https://t.me/addemoji/TgAndroidIcons): в сообщениях — custom emoji, на кнопках — встроенные иконки Telegram. Если Telegram не разрешит custom emoji, бот пробует обычные emoji как запасной вариант.

**Важно:** для отображения именно custom emoji у владельца бота должен быть Telegram Premium. Иконки в сообщениях доступны в личных чатах, группах и супергруппах; посты, публикуемые в канал, остаются исходным содержимым пользователя.

## Настройка

1. Создай бота через @BotFather.
2. Установи зависимости: pip install -r requirements.txt.
3. Укажи BOT_TOKEN в переменных окружения хостинга или в локальном .env.
4. Укажи MODERATION_CHAT_ID — ID группы, куда приходят заявки и кнопки.
5. Укажи DESTINATION_CHAT_ID — ID отдельного канала, куда отправлять принятые предложения. Эти ID должны быть разными, если нужна публикация из группы в канал.
6. Добавь бота в группу модерации. Команда /id в группе покажет её фактический ID, а также эффективные значения настроек модерации и публикации, которые реально видит запущенный процесс. Для канала добавь бота администратором с правом публикации и укажи ID именно канала.
7. На BotHost команда запуска — python main.py. После изменения кода или переменных окружения полностью перезапусти приложение, чтобы запустился новый процесс.

Пример переменных окружения:

- BOT_TOKEN — новый токен бота.
- MODERATION_CHAT_ID=-5106639548 — группа модерации (пример).
- DESTINATION_CHAT_ID=-1001234567890 — отдельный канал публикации (пример; используй свой реальный ID).
- DB_PATH=/data/suggestions.sqlite3 — необязательно; путь к базе SQLite.

Если используется существующая SQLite-база, старые заявки и блокировки сохраняются. Явная переменная DESTINATION_CHAT_ID имеет приоритет над старым адресом, сохранённым в базе.

## Важно

- Не добавляй токен в GitHub. Храни его только в защищённых переменных окружения хостинга.
- Не запускай два экземпляра polling-бота одновременно с одним токеном.
- Если /start не отвечает после деплоя, проверь логи запуска: в них должно быть Started as @... . Убедись, что хостинг запустил нужную ветку и что не работает второй экземпляр бота с тем же токеном.
- Если в логах написано, что группа модерации и канал публикации имеют одинаковый ID, бот не будет считать заявку опубликованной: укажи разные ID.
- Если текст нужно опубликовать вместе с фото или видео, отправляй текст именно в подписи к медиа. Telegram не позволяет превратить два отдельно отправленных сообщения в одно без изменения исходного содержимого.
