# Предложка с модерацией в группе

Telegram-бот на Python 3.11+ и aiogram 3. Пользователь отправляет сообщение боту в личку, а заявка и карточка с кнопками появляются в группе модерации. Отдельные администраторы и их личные чаты не нужны: кнопками может пользоваться любой участник группы.

## Возможности

- Поддерживаются текст, фото, видео, кружки, голосовые, GIF, стикеры, файлы и альбомы.
- Копия предложения и карточка с кнопками приходят в группу модерации.
- Принять — публикует предложение в целевом чате.
- Отклонить — сообщает отправителю, что предложение не принято.
- Ответить — участник группы отвечает на сообщение-подсказку прямо в группе; ответ уходит пользователю в личку с цитатой его предложения.
- Заблокировать — блокирует пользователю отправку новых предложений. Блокировки сохраняются в SQLite.
- Команда /unblock USER_ID в группе модерации снимает блокировку. Любой участник этой группы может выполнить её.
- После решения кнопки убираются, повторно обработать заявку нельзя.

## Настройка

1. Создай бота через @BotFather.
2. Установи зависимости: pip install -r requirements.txt.
3. Укажи BOT_TOKEN в переменных окружения хостинга или в локальном .env.
4. Укажи MODERATION_CHAT_ID — ID группы, куда приходят заявки и кнопки. Если переменная пустая, используется DESTINATION_CHAT_ID.
5. Укажи DESTINATION_CHAT_ID — чат или канал, куда отправлять принятые предложения. Если это та же группа, где стоят кнопки, бот не будет копировать сообщение второй раз.
6. Добавь бота в группу модерации и проверь, что он может отправлять туда сообщения. Для публикации в канале добавь бота администратором с правом публикации.
7. На BotHost команда запуска — python main.py. После изменения кода перезапусти приложение, чтобы запустился новый процесс.

Пример переменных окружения:

- BOT_TOKEN — новый токен бота.
- MODERATION_CHAT_ID=-1001234567890 — группа модерации.
- DESTINATION_CHAT_ID=-1001234567890 — место публикации; можно указать другой ID, если публикация должна идти в отдельный канал.
- DB_PATH=/data/suggestions.sqlite3 — необязательно; путь к базе SQLite.

Если используется существующая SQLite-база, старые заявки и блокировки сохраняются. Явная переменная DESTINATION_CHAT_ID имеет приоритет над старым адресом, сохранённым в базе.

## Важно

- Не добавляй токен в GitHub. Храни его только в защищённых переменных окружения хостинга.
- Не запускай два экземпляра polling-бота одновременно с одним токеном.
- Если /start не отвечает после деплоя, проверь логи запуска: в них должно быть Started as @... . Убедись, что хостинг запустил нужную ветку и что не работает второй экземпляр бота с тем же токеном.
